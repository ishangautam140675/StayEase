7. Top Viva Questions & Winning Academic Answers

Q1 How does StayEase prevent race conditions and double-booking?
"We enforce database-level PESSIMISTIC_WRITE row locking (SELECT ... FOR UPDATE) inside a @Transactional(isolation = Isolation.READ_COMMITTED) boundary. When User A begins booking, that specific room row is locked until commit. If User B attempts to book the same room concurrently, their transaction waits, and subsequently fails when our interval validation detects the overlapping stay: (existing.checkIn < new.checkOut) AND (existing.checkOut > new.checkIn)."
Q2 Why did you use OpenStreetMap instead of Google Maps API?
"Google Maps requires mandatory credit card billing and charges significant fees per API request, which creates financial liability. OpenStreetMap (Overpass & Nominatim) paired with Komoot Photon is community-powered, 100% free of cost, provides worldwide coverage, and offers unrestricted programmatic access to raw geographical tags without billing limits."
Q3 What is the difference between Spring, Spring Boot, and Spring Data JPA?
"Spring is the underlying inversion-of-control container requiring XML/Java configuration. Spring Boot eliminates boilerplate via auto-configuration and embeds a Tomcat server for standalone execution. Spring Data JPA is the data persistence layer built on Hibernate that converts Java Entity objects into relational database queries without writing manual SQL."
Q4 How does the typeahead search box avoid lagging the browser or server?
"We implemented client-side debouncing with a 220-millisecond delay. Keystrokes reset a timer and only fire the HTTP fetch request after the user pauses typing for 220ms. In addition, client-side memory cache and backend ConcurrentHashMap caching prevent redundant network calls for identical queries."
Q5 How do you securely store user passwords?
"Passwords are never stored in plaintext. We use Spring Security's BCryptPasswordEncoder, an adaptive one-way hashing algorithm with a cryptographic work factor (strength = 10) and an automated random salt per user. Even if two users share the same password, their database hashes are completely distinct, neutralizing rainbow table attacks."
Q6 How is the distance between the user and accommodations calculated?
"We implemented the Haversine Formula in Java (calculateDistanceKm(lat1, lon1, lat2, lon2)). Because the Earth is spherical, 2D Euclidean distance (Pythagorean theorem) fails for coordinates. The Haversine formula applies spherical trigonometry to compute the true great-circle surface distance in kilometers."
Q7 What are ADR and RevPAR in your Admin Dashboard?
"ADR (Average Daily Rate) is the average revenue earned per paid occupied room: ADR = Total Room Revenue / Rooms Sold. RevPAR (Revenue Per Available Room) evaluates overall property efficiency across total capacity: RevPAR = ADR × Occupancy Rate."
Q8 What is CSRF and how does StayEase defend against it?
"Cross-Site Request Forgery (CSRF) occurs when an unauthorized site exploits authenticated browser credentials to submit unauthorized commands. StayEase uses Spring Security's synchronized token pattern: every state-changing POST/PUT form contains a hidden cryptographic CSRF token validated on the server."
Q9 How do you prove your system is bug-free and production-ready?
"We engineered a comprehensive automated test suite of 295+ tests utilizing JUnit 5, Mockito, and MockMvc. The tests exercise authentication, role authorization, concurrency race conditions, date validation, and API endpoints, maintaining a 100% pass rate."
